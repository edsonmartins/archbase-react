## Uso Básico

`ArchbasePasswordEdit` é um campo de senha com botão para mostrar/ocultar o conteúdo, integração automática ao DataSource e suporte a validação.

### Como funciona

```tsx
<ArchbasePasswordEdit
  dataSource={dataSource}
  dataField="senha"
  label="Senha"
/>
```

O componente:
- **Em modo browse**: fica somente leitura automaticamente
- **Em modo edit/insert**: permite edição com toggle de visibilidade
- **Sincroniza**: valor bidirecional com o DataSource
- **Valida**: erros são exibidos automaticamente
- **Protege**: o valor nunca é exibido em texto plain no modo de visualização

## Segurança

### Toggle de Visibilidade

O componente inclui um botão para mostrar/ocultar a senha:

```tsx
<ArchbasePasswordEdit
  label="Senha"
  placeholder="Digite sua senha..."
/>
```

O ícone de "olho" permite ao usuário:
- **Ocultar** (padrão): mostra `••••••••`
- **Mostrar**: revela a senha digitada temporariamente

### Boas Práticas

1. **Sempre use HTTPS** em produção
2. **Valide no backend** - nunca confie apenas na validação frontend
3. **Use requisitos de complexidade** - exija letras, números e caracteres especiais
4. **Limite o tamanho** - senhas muito longas podem causar problemas
5. **Nunca log senhas** - em console, arquivos ou serviços externos

## Senha forte

A partir da versão 4.0.42, a prop `passwordPolicy` faz a pré-validação de senha forte
no próprio componente, exibindo a barra de força e a lista de critérios:

```tsx
<ArchbasePasswordEdit
  label="Senha"
  dataSource={dataSource}
  dataField="password"
  passwordPolicy
/>
```

`passwordPolicy` sozinha (ou `passwordPolicy={true}`) aplica a política padrão:
8 caracteres, ao menos uma letra minúscula, uma maiúscula, um número, um símbolo
e nenhum espaço em branco.

O feedback aparece enquanto o usuário digita, mas a mensagem de erro no campo só
é exibida quando ele sai do campo — para não acusar erro já na primeira tecla.

**Compatibilidade:** sem a prop `passwordPolicy` nada muda — o componente se
comporta exatamente como nas versões anteriores.

### Ajustando os critérios

```tsx
<ArchbasePasswordEdit
  label="Senha"
  dataSource={dataSource}
  dataField="password"
  passwordPolicy={{
    minLength: 12,
    minUppercase: 1,
    minNumbers: 1,
    minSymbols: 0,
    forbidWhitespace: true,
    forbidRepeated: 3,
    forbidSequential: 4,
    blocklist: ['archbase', usuario.email?.split('@')[0]]
  }}
  passwordRequirementsVisibility="always"
/>
```

| Critério | Tipo | Descrição |
|----------|------|-----------|
| `minLength` | `number` | Quantidade mínima de caracteres |
| `maxLength` | `number` | Quantidade máxima de caracteres |
| `minLowercase` | `number` | Mínimo de letras minúsculas |
| `minUppercase` | `number` | Mínimo de letras maiúsculas |
| `minNumbers` | `number` | Mínimo de dígitos |
| `minSymbols` | `number` | Mínimo de caracteres não alfanuméricos |
| `forbidWhitespace` | `boolean` | Proíbe espaços em branco |
| `forbidRepeated` | `number` | Proíbe N caracteres iguais seguidos (`3` rejeita `aaa`) |
| `forbidSequential` | `number` | Proíbe N caracteres em sequência (`4` rejeita `1234` e `dcba`) |
| `blocklist` | `string[]` | Termos proibidos dentro da senha, sem diferenciar maiúsculas |

Um critério ausente ou igual a zero simplesmente não é avaliado.

### Props de senha forte

| Prop | Tipo | Padrão | Descrição |
|------|------|--------|-----------|
| `passwordPolicy` | `ArchbasePasswordPolicy \| boolean` | — | Critérios exigidos. `true` aplica a política padrão |
| `showPasswordRequirements` | `boolean` | `true` | Exibe a lista de critérios |
| `showPasswordStrengthBar` | `boolean` | `true` | Exibe a barra de força |
| `passwordRequirementsVisibility` | `'always' \| 'onFocus' \| 'whenInvalid'` | `'onFocus'` | Quando o feedback fica visível |
| `onPasswordValidation` | `(result) => void` | — | Disparado a cada mudança no resultado da validação |

### Reagindo ao resultado

```tsx
const [podeSalvar, setPodeSalvar] = useState(false);

<ArchbasePasswordEdit
  label="Senha"
  dataSource={dataSource}
  dataField="password"
  passwordPolicy
  onPasswordValidation={(result) => setPodeSalvar(result.valid)}
/>
```

**Atenção:** esta é uma validação de entrada, executada no navegador e portanto
contornável. Aplique a mesma política também no backend.

## Validação por decorators

Para validar junto com o restante do modelo, use os decorators do `@archbase/core`:

```tsx
import { IsNotEmpty, MinLength, Matches } from '@archbase/core';

class Usuario {
  @IsNotEmpty({ message: 'Senha é obrigatória' })
  @MinLength(8, { message: 'Senha deve ter pelo menos 8 caracteres' })
  @Matches(/^(?=.*[a-z])(?=.*[A-Z])(?=.*\d)(?=.*[@$!%*?&])[A-Za-z\d@$!%*?&]/, {
    message: 'Senha deve conter letra maiúscula, minúscula, número e caractere especial'
  })
  senha: string;
}
```

Os dois mecanismos são complementares: `passwordPolicy` dá o feedback visual
enquanto o usuário digita, e o decorator garante a regra na validação do modelo.

## Acessibilidade

O `ArchbasePasswordEdit` segue as melhores práticas de acessibilidade:

- Labels associadas corretamente via `htmlFor`
- Tipo `password` no input HTML para segurança nativa
- Toggle de visibilidade acessível por teclado
- Erros anunciados via `aria-describedby`
- Campos obrigatórios indicados via `aria-required`
- Compatível com screen readers
- `aria-label` no botão de toggle

## Dicas de Performance

### DataSource V2

O DataSource V2 oferece otimizações de performance:

```tsx
// V2 detectado automaticamente
const { dataSource } = useArchbaseDataSourceV2<Usuario>({
  initialData: usuarios,
  name: 'dsUsuarios',
});

// O componente usa re-renders otimizados internamente
<ArchbasePasswordEdit dataSource={dataSource} dataField="senha" />
```

### Evite re-renders desnecessários

```tsx
// Ruim: cria nova função a cada render
<ArchbasePasswordEdit onChangeValue={(e, v) => setValue(v)} />

// Bom: callback estável
const handleChange = useCallback((e, v) => setValue(v), []);
<ArchbasePasswordEdit onChangeValue={handleChange} />
```

### Indicador de força

Não é necessário calcular a força manualmente: use a prop `passwordPolicy`
(ver [Senha forte](#senha-forte)) ou, se precisar do medidor ao lado de um input
próprio, o componente `ArchbasePasswordStrengthMeter`:

```tsx
import { PasswordInput } from '@mantine/core';
import { ArchbasePasswordStrengthMeter } from '@archbase/components';

function PasswordWithStrength() {
  const [password, setPassword] = useState('');

  return (
    <Stack>
      <PasswordInput
        label="Senha"
        value={password}
        onChange={(event) => setPassword(event.currentTarget.value)}
      />
      <ArchbasePasswordStrengthMeter value={password} policy={{ minLength: 10 }} />
    </Stack>
  );
}
```
