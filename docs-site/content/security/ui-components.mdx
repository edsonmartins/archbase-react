
# Componentes de UI de Segurança

Modais e formulários para gerenciamento de segurança.

## ArchbaseLogin

Formulário de login, exportado por `@archbase/security`.

```tsx
import { ArchbaseLogin } from '@archbase/security';

<ArchbaseLogin
  onLogin={handleLogin}
  error={loginError}
  onClickForgotPassword={() => navigate('/reset-password')}
/>
```

## UserModal

Modal de cadastro e edição de usuários. Os modais de segurança são orientados a
DataSource: recebem `dataSource`, `opened` e os callbacks `onClickOk` /
`onClickCancel`.

```tsx
import { UserModal } from '@archbase/security-ui';

<UserModal
  dataSource={dsUsuario}
  opened={userModalOpened}
  onClickOk={(record) => salvarUsuario(record)}
  onClickCancel={() => setUserModalOpened(false)}
/>
```

### Exigindo senha forte

A option `passwordPolicy` liga a validação de senha forte no campo de senha,
com barra de força e lista de critérios:

```tsx
<UserModal
  dataSource={dsUsuario}
  opened={userModalOpened}
  onClickOk={(record) => salvarUsuario(record)}
  onClickCancel={() => setUserModalOpened(false)}
  options={{ passwordPolicy: true }}
/>
```

| Option | Tipo | Padrão | Descrição |
|--------|------|--------|-----------|
| `passwordPolicy` | `ArchbasePasswordPolicy \| boolean` | - | Critérios de senha forte. `true` aplica a política padrão |
| `showPasswordRequirements` | `boolean` | `true` | Exibe a lista de critérios abaixo do campo |
| `forbidPersonalDataInPassword` | `boolean` | `true` | Impede que a senha contenha o nome, o apelido ou o e-mail do usuário |

`forbidPersonalDataInPassword` só tem efeito quando `passwordPolicy` está ativa.
Na **edição**, senha em branco continua significando "manter a senha atual" e não
é validada.

/>
